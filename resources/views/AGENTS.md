# AGENTS.md

## Назначение

Клиентская часть Elitvid: публичный сайт и админка на Blade. Правила бэкенда и репозитория — в `Elitvid_v2/AGENTS.md`. Здесь только вьюхи, стили и скрипты.

## Карта

- `layouts/elitvid/elitvid.blade.php` — каркас публичных страниц: подключает CSS и JS, шапку, reCAPTCHA, аналитику.
- `layouts/elitvid/admin/admin.blade.php` — каркас и меню админки. Пункты меню зависят от роли (`$authRole`).
- `elitvid/site/` — публичные страницы. `elitvid/admin/` — экраны админки.
- `includes/elitvid/` — куски страниц (окно заявки, хлебные крошки, каталог), `includes/elitvid/admin/` — формы админки.
- `components/elitvid/` — Blade-компоненты нового вида: шапка, подвал, кнопка, поле, карточки. Остальное в `components/` и `auth/` — стандартный скелет Breeze.
- `mail/` — шаблоны писем.
- Стили и скрипты — `public/elitvid_assets/`: новый вид в `newDesign/newDesign/` (`style.css`, `reset.css`, `js/`), редизайн в `redesign/` (`redesign.css`, `redesign.js`, `cart-add.js`), админка в `js/` и `css/`.
- `resources/js/` (React, Inertia) и `resources/css/app.css` — неиспользуемый скелет Breeze: ни один маршрут не отдаёт Inertia, ни публичный, ни админский каркас не подключают Vite. Новый экран на React без спеки не заводить.

## Архитектура

- Стек: Blade с серверным рендером. Публичная часть — jQuery 3.7 и Swiper, админка — jQuery, Bootstrap и TinyMCE. Новых библиотек интерфейса и сборщика без спеки не добавлять.
- Страница показывает то, что отдал контроллер через `view(...)`. Правило предметной области (доступен ли товар, можно ли оформить заказ) считает бэкенд, вьюха берёт готовое значение, как `canOrder` в корзине.
- Новый вид описывается в `redesign/redesign.css`. Скрипт нужен для поведения, которое CSS не даёт: меню, список контактов, форма, кнопка корзины.
- Повторяемую часть нового вида выносить в `components/elitvid/`, а не копировать в страницы.
- Ссылки — через `route('имя')`, имена брать в `routes/web.php`.
- Форма — обычный `POST` с `@csrf` и `g-recaptcha-response`. Заявка идёт на `send_mail`, корзина — на `cart.*`. Имена полей берутся из Form Request (`MailRequest`, `PlaceOrderRequest`: `name`, `email`, `phone`, `country`, `name_corp`, `textarea`).
- Тексты страниц, статьи блога, картинки слотов хранятся в базе и правятся в админке. Текст, который уже редактируется там, во вьюху не хардкодить.
- Тексты интерфейса — на русском.

## Жёсткие инварианты

- Маршрут и поле формы брать из `routes/web.php` и Form Request. URL и имена полей не придумывать.
- Скрытая по роли кнопка или пункт меню не заменяет `role.access` и `deny.roles` в `routes/web.php`.
- Менялся `style.css` или `redesign.css` — поднять `?v=` у ссылки на файл в `layouts/elitvid/elitvid.blade.php`. Иначе браузер покажет старый кэш.
- Файлы `*.min.js` и `*.min.css` руками не править.
- Вёрстку проверять на широком (1440 px) и узком (320 px) экране. Горизонтальную прокрутку страницы не добавлять.
- Файлы изображений с хостинга (`storage/app/public`, `public/elitvid_assets/newDesign/newDesign/files`) в git не входят. Не коммитить.
- Пока идёт `/elitvid-docs`, вьюхи, стили и скрипты не менять.
- Вид админки без спеки не менять.

## Проверка перед «готово»

- Фронтовых тестов нет: в `package.json` только `dev` и `build`.
- Открыть затронутую страницу на http://localhost:8080 на 1440 и 320 px. Если у спеки есть `quickstart.md`, пройти его сценарий.
- Админку проверять входом через `ADMIN_EMAIL` и `ADMIN_PASSWORD` из `.env`. Значения в чат и в документы не копировать.
