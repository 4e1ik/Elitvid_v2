# Адаптация генерации документации Elitvid

## Цель

Переписать копию kit в `aidocumentation` под один сайт Elitvid и подключить её к общему окну Cursor вместе со spec-kit. Готовые документы лежат в git сайта. Первая запись этих документов — следующий запуск `/elitvid-docs`, после отдельного «да» на план файлов.

Эта спека не ставит spec-kit и не пишет текст документов сайта. Установка spec-kit описана в `2026-11-14-spec-kit-setup-design.md`; текст `AGENTS.md` и раздел про подключение документации там приведены к этой спеке.

## Окно

Cursor открыт на `/Users/artemi/projects/Elitvid`. Эта папка не git. Внутри два репозитория:

| Путь | Git | Роль |
|---|---|---|
| `Elitvid_v2` | да | сайт, spec-kit, готовые документы |
| `aidocumentation` | да | исходник команд документации |

Команды видны окну через символические ссылки. Живые копии навыков в родительской папке не хранятся.

Скрипт `aidocumentation/scripts/link-workspace.sh` создаёт ссылки и заново записывает `Elitvid/AGENTS.md` из шаблона `aidocumentation/templates/workspace-AGENTS.md`. Шаблон — источник текста. Повторный запуск нужен после обновления spec-kit или kit.

`Elitvid/.cursor/skills/` и `Elitvid/.cursor/rules/` — обычные каталоги. Ссылками являются записи внутри них, не сами каталоги. Иначе навыки spec-kit и документации не смогут стоять рядом.

| В окне | Куда |
|---|---|
| `Elitvid/.cursor/skills/speckit-*` | каждый навык `Elitvid_v2/.cursor/skills/speckit-*` |
| `Elitvid/.cursor/skills/<команда документации>` | каждый навык `aidocumentation/.cursor/skills/` |
| `Elitvid/.cursor/rules/specify-rules.mdc` | `Elitvid_v2/.cursor/rules/specify-rules.mdc` |

Скрипт запускается после `specify init`. Нет `Elitvid_v2/.cursor/skills/speckit-plan` — скрипт останавливается и пустые ссылки не создаёт.

В `Elitvid_v2/.cursor` навыки документации не копируются. Правила Guru и `kit-safety.mdc` в окно не ссылаются.

Всегда включено только `specify-rules.mdc`. Запрет менять код и писать в базу во время документации записан в навыке `/elitvid-docs`.

Корень spec-kit — `Elitvid_v2`. Фичи пишутся в `Elitvid_v2/specs/`. Ссылку `.specify` в родительской папке не ставим: скрипты spec-kit из окна задают `SPECIFY_INIT_DIR` на каталог `Elitvid_v2`, где лежит `.specify`, иначе их запускают изнутри `Elitvid_v2`. Обычный каталог `.specify` или `specs` в родительской папке не оставляем: каталог удаляется и причина записывается в отчёт.

| Что | Путь | Репозиторий |
|---|---|---|
| Фича | `Elitvid_v2/specs/<фича>/` | сайт |

| Текст для человека | `Elitvid_v2/docs/human/` | сайт |
| Черновики чатов | `Elitvid_v2/docs/superpowers/` | сайт |
| Команды документации | `aidocumentation` | kit |

`.specify/memory/constitution.md` и `docs/ai/CONSTITUTION.md` не склеиваются. Первый — правила нового кода. Второй — карта уже работающей системы. В каждом файле одна ссылка на другой.

`docs/superpowers/` в `specs/` не переносится.

## Два AGENTS.md

Тексты согласованы. Противоположных приказов нет.

Родительский файл пишет скрипт из `aidocumentation/templates/workspace-AGENTS.md`:

```md
# Elitvid

Окно Cursor — эта папка. Сайт — `Elitvid_v2` (Laravel 10, PHP 8.1, Docker, http://localhost:8080, подъём `make init`). Команды документации — репозиторий `aidocumentation`.

## Куда смотреть

- Новая фича сайта — spec-kit в `Elitvid_v2`: `specs/<фича>/`. Принципы нового кода — `Elitvid_v2/.specify/memory/constitution.md`. Команды — `/speckit-*`. Корень spec-kit — `Elitvid_v2`. Скрипты spec-kit из родительского окна должны задавать `SPECIFY_INIT_DIR` на каталог `Elitvid_v2`, в котором лежит `.specify`. Без этой переменной запускайте их изнутри `Elitvid_v2`.
- Как система устроена сейчас — `Elitvid_v2/docs/ai/` (для AI) и `Elitvid_v2/docs/human/` (для человека). Пишет `/elitvid-docs`.
- Черновики обсуждений — `Elitvid_v2/docs/superpowers/`. В `specs/` их не переносить.

## Границы

- Пока идёт `/elitvid-docs`: код приложения, миграции и базу не менять. Базу `elitvid_db` можно только читать (`SELECT`).
- Менять код и базу можно задачей spec-kit по спеке в `Elitvid_v2/specs/`.
- `.specify/` и `.cursor/skills/speckit-*` внутри `Elitvid_v2` обновляет spec-kit.
- Команды документации обновляет репозиторий `aidocumentation`. В `Elitvid_v2` их не копировать.
- Всегда включённое правило окна — только правило spec-kit. Запреты документации включены внутри `/elitvid-docs`.
```

Файл сайта пишется вручную в `Elitvid_v2/AGENTS.md`. Spec-kit его не создаёт и при обновлении не затирает.

```md

Laravel 10, PHP 8.1, Docker. Сайт: http://localhost:8080. Подъём: `make init` (см. README.md).

## Куда смотреть

- Навыки и правила kit документации в этот репозиторий не копировать.
```

## Документы

Оба слоя на русском. Слой AI короткий: что это, где в коде, какие роли и входы. Слой для человека объясняет поведение предложениями.

AI:

| Файл | Содержание |
|---|---|
| `docs/ai/CONSTITUTION.md` | продукт, стек, роли, куда смотреть в коде, ссылка на конституцию spec-kit |
| `docs/ai/SERVICE_MAP.md` | модули и точки входа по коду |
| `docs/ai/graphify-out/` | граф кода, если CLI `graphify` установлен |

Человек, без файла на каждый URL:

| Файл | Содержание |
|---|---|
| `docs/human/obzor.md` | сайт целиком: главная, направления, статические страницы, как контент из админки попадает на сайт |
| `docs/human/katalog.md` | скамейки, кашпо, болларды и ограждения |
| `docs/human/blog.md` | блог |
| `docs/human/zayavki.md` | форма на сайте и заявки в админке |
| `docs/human/admin.md` | разделы админки и роли по маршрутам |

Роли берутся из маршрутов и middleware. На момент спеки в коде есть `admin`, `manager`, `viewer`. Матрицу прав генератор читает из кода в момент запуска, а не из этой спеки.

Статические страницы и контент страниц входят в `obzor.md` и `admin.md`. Отдельного файла для них нет.

Скриншоты лежат рядом с человеческим файлом, который они иллюстрируют. Кадра на каждый URL нет. Пароль в кадр, чат и markdown не попадает. Когда сайт отвечает на `http://localhost:8080` и логин админки есть — два кадра: публичный сайт и главная админки. Дополнительный кадр допустим, если без него раздел непонятен. Нет логина — только публичный кадр, пропуск админки назван в плане. Сайт не отвечает — кадров нет, это тоже названо в плане.

Граф коммитится вместе с документами только по отдельной просьбе закоммитить. Перед добавлением в git размер `docs/ai/graphify-out/` сравнивается с суммарным размером markdown в `docs/ai/` и `docs/human/`. Каталог графа больше — в git он не добавляется, об этом говорится пользователю.

## Команда `/elitvid-docs`

Одна команда. Команд на экран, на ветку фичи и на публикацию после деплоя нет.

Порядок:

1. Читает код `Elitvid_v2`.
2. Читает локальную базу только `SELECT`. Параметры — `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD` и `DB_PORT` из `Elitvid_v2/.env`. Порт по умолчанию `3306`. Подключение с машины пользователя на `127.0.0.1`, потому что `DB_HOST=mysql` резолвится только внутри Docker. Пароль в чат и в документы не копируется. Нет подключения — в план добавляется одна фраза, что база не прочитана и факты возьмутся из кода. Файлы по-прежнему пишутся только после «да».
3. Показывает план файлов: что создаст или какой кусок обновит. Скриншоты и граф в том же плане.
4. Пишет после «да», «ок» или «план верный». Молчание планом не считается. «Нет» — план переписывается, файлы не пишутся.
5. Код приложения, миграции, конфиги и базу не меняет. `INSERT`, `UPDATE`, `DELETE`, сиды и `artisan` с записью запрещены.
6. Уже существующий файл правит по затронутым разделам. Полная перезапись — только если файла ещё нет.
7. Снимает обзорные скриншоты с `http://localhost:8080` по правилу раздела «Документы».
8. Обновляет граф командой `graphify`, если CLI есть. Нет CLI — остановка до записи графа: сказать, что нужен `graphify`, markdown при подтверждённом плане записать, каталог графа не выдумывать.

Факты только из кода, маршрутов и прочитанной базы. Эндпоинты, роли и поля не выдумывать.

## Что остаётся в kit и что уходит

`aidocumentation` переписывается под Elitvid. Остаются: план до записи, запрет выдумывать, запрет менять код и базу внутри `/elitvid-docs`, шаблоны `CONSTITUTION.md` и `SERVICE_MAP.md` с путями `Elitvid_v2/docs/ai/`, вызов `graphify`.

Уходят навыки, правила, MCP и инструкции, которые существуют для экранов, Confluence, Jira, Grafana, Mongo, нескольких продуктов Guru и публикации в отдельный репозиторий документов. В том числе `docsdevarea`, `docsdevarea-screen`, `docsdevarea-main`, `confluence-publish`, `vue-screen-map`, правила `paymentguru-*` и `chat-backend-context`, `kit-safety.mdc` как всегда включённое правило, `.cursor/mcp.json` с Atlassian и Grafana.

`README.md`, `AGENTS.md` kit и `docs/instrukciya.md` описывают окно `Elitvid`, команду `/elitvid-docs` и локальную базу. Адресов Guru, Confluence и Grafana в них нет.

Карта репозиториев — одна продуктовая строка: папка `Elitvid_v2`, имя `Elitvid`, стек `laravel`, зона «сайт и админка». Сам kit в карту не входит.

Figma, Grafana, Jira и Confluence в эту адаптацию не входят. Места под них в MCP и в команде нет.

## Проверка

- В родительской папке ссылки из таблицы «Окно» указывают на файлы двух репозиториев. Обычных копий навыков нет.
- `Elitvid/.cursor/rules/` содержит только ссылку на `specify-rules.mdc`.
- `Elitvid_v2/.cursor/skills/` не содержит `elitvid-docs`, `docsdevarea`, `docsconnect`.
- `Elitvid_v2/AGENTS.md` совпадает с текстом этой спеки.
- `aidocumentation` не содержит навыков Confluence, экранов Guru, MCP Grafana и Atlassian.
- Код приложения, `composer.json`, Docker и `README.md` сайта эта адаптация не меняет.
- Каталога `specs/<фича>/` адаптация не создаёт.
- Текст `docs/ai/` и `docs/human/` пишет только `/elitvid-docs` после «да».

## Чего эта спека не делает

- Не запускает `specify init`.
- Не пишет первую версию `docs/ai/` и `docs/human/`.
- Не подключает Figma.
- Не коммитит результат, пока это не попросили отдельно.
