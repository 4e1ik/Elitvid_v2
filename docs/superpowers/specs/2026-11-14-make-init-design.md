# make init — один запуск локального окружения

## Цель

`make init` поднимает проект локально одной командой: контейнеры, база `elitvid_db`, импорт дампа, `composer install`, ключ приложения, симлинк `storage` и миграции.

Скрипт ничего не скачивает. Дамп и картинки пользователь кладёт сам. Если их нет, команда спрашивает, продолжать без них или остановиться. Если база уже заполнена, команда спрашивает, оставить данные или залить дамп заново.

## Команда

`make init` вызывает `scripts/init.sh`. Логика живёт в скрипте, не в рецепте Makefile.

Порядок:

1. `docker compose up -d --build`. Образ пересобирается, только если изменился контекст сборки. Контейнеры и том базы не пересоздаются принудительно.
2. Ждать, пока MariaDB примет подключение, до 60 секунд. Иначе выйти с ошибкой.
3. Проверить дамп и картинки.
4. Задать вопросы, если они нужны.
5. Привести базу к выбранному варианту.
6. Если пользователь не остановил команду: поставить PHP-зависимости и подготовить Laravel.

`make db-import` и `make app` остаются как есть. Импорт по-прежнему читает `cr48940_elitvid_ordered.sql`.

## Проверки файлов

Дамп есть, если в корне лежит `cr48940_elitvid.sql`.

Картинки есть, если выполнены оба условия:

- в `storage/app/public/` есть хотя бы один файл, кроме `.gitignore`;
- каталог `public/elitvid_assets/newDesign/newDesign/files/` существует и в нём есть хотя бы один файл.

Каталог `public/elitvid_assets/newDesign/newDesign/imgs/` уже в git. Его отсутствие не спрашивается.

Перед импортом скрипт сам собирает `cr48940_elitvid_ordered.sql` из сырого дампа: в начало пишет `SET FOREIGN_KEY_CHECKS=0;` и `SET NAMES utf8mb4;`, в конец — `SET FOREIGN_KEY_CHECKS=1;`.

## Вопросы в терминале

Ответы читаются из `/dev/tty`. Неверный ввод спрашивается снова. Принимаются `1` и `2`.

Если не хватает дампа, картинок или обоих, скрипт печатает, чего нет, и спрашивает:

1. Продолжить с тем, что уже лежит в проекте.
2. Остановиться.

Остановка завершает команду с ненулевым кодом. Базу, `vendor` и `.env` она не меняет. Контейнеры к этому моменту уже запущены.

Если дамп есть и в `elitvid_db` уже есть таблицы, скрипт спрашивает:

1. Оставить данные.
2. Удалить базу и импортировать дамп заново.

Если дампа нет, вопрос про переимпорт не задаётся: существующие таблицы не удаляются.

Если терминала нет и вопрос обязателен:

- не хватает дампа или картинок — остановиться с тем же текстом, базу не менять;
- база уже заполнена, а дамп на месте — оставить данные и идти дальше.

## База

В `docker-compose.yml`:

- `MYSQL_DATABASE=elitvid_db`;
- healthcheck: `mysqladmin ping` каждые 5 секунд, timeout 5 секунд, 12 попыток;
- именованный том `mysql_data` на `/var/lib/mysql`.

Готовность базы определяет сам скрипт: `mysqladmin ping` раз в 2 секунды, не дольше 60 секунд. Healthcheck в compose нужен, чтобы состояние контейнера было видно в `docker compose ps`.

Сейчас данные MariaDB лежат внутри контейнера, без тома. После смены compose новый том будет пустым, а старые данные в новый том не переедут. Первый `make init` после этой смены увидит пустую базу и, если дамп есть, импортирует его без вопроса про перезапись.

Скрипт всё равно выполняет `CREATE DATABASE`, потому что `MYSQL_DATABASE` срабатывает только на пустом томе:

```sql
CREATE DATABASE IF NOT EXISTS elitvid_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
ALTER DATABASE elitvid_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

Учётные данные те же: пользователь `root`, пароль `root`, контейнер `elitvid_db`.

Действие с базой:

| Ситуация | Что делает скрипт |
|---|---|
| Дампа нет, таблиц нет | Создать пустую `elitvid_db`. Импорт и `migrate` пропустить |
| Дампа нет, таблицы есть | Ничего не удалять. `migrate` выполнить |
| Дамп есть, таблиц нет | Создать базу, собрать ordered-файл, импортировать, затем `migrate` |
| Дамп есть, таблицы есть, пользователь оставил данные | Не импортировать. `migrate` выполнить |
| Дамп есть, таблицы есть, пользователь выбрал переимпорт | `DROP DATABASE`, создать заново, импортировать, затем `migrate` |

База `wd05`, созданная прежним compose, не используется и не удаляется. Новые тома её больше не создают.

Импорт идёт той же командой, что и `make db-import`. Если импорт падает, скрипт останавливается и не запускает `migrate`.

## Приложение

Эти шаги выполняются, только если пользователь не выбрал остановку. Команды идут в контейнере `php_elitvid`.

1. `composer install --no-interaction`. Ошибка composer останавливает скрипт.
2. `php artisan key:generate`, только если в `.env` нет значения `APP_KEY`. Существующий ключ не перезаписывается. Отсутствующий `.env` — ошибка, скрипт его не создаёт.
3. `php artisan storage:link`. Уже существующий симлинк считается успехом.
4. `php artisan migrate --force` — только в строках таблицы выше, где `migrate` указан. На пустой базе миграции не запускаются: они завершаются ошибкой и мешают последующему импорту.

`.env` пользователя не переписывается. `DB_HOST=elitvid_db` уже резолвится в сети compose.

## Повторный запуск

Повторный `make init` безопасен. Он не удаляет том и не заливает дамп заново, пока пользователь явно не выберет переимпорт. `composer install` и `storage:link` можно выполнять повторно.

## README

Раздел запуска описывает новый порядок:

1. Положить `cr48940_elitvid.sql` в корень.
2. Положить загруженные картинки в `storage/app/public/` и `public/elitvid_assets/newDesign/newDesign/files/`.
3. Запустить `make init`.

Ручное создание базы и ручная сборка ordered-файла уходят из основного сценария. Обновление данных с хостинга — это новый дамп, новые картинки и повторный `make init` с ответом «импортировать заново». `make db-import` остаётся отдельной командой для уже собранного `cr48940_elitvid_ordered.sql`.

## Вне скоупа

- Скачивание дампа и картинок.
- Правка `.env` и `.env.example`.
- Удаление базы `wd05` из старого тома.
- Отдельная команда для выборочного импорта картинок.
- Обход несовместимости `composer.lock` с PHP 8.1.

## Проверка

- При наличии дампа и картинок `make init` заканчивается базой `elitvid_db` с таблицами, установленным `vendor`, симлинком `public/storage` и ответом `http://localhost:8080`.
- Повторный запуск спрашивает про уже заполненную базу и без выбора «переимпорт» таблицы не сносит.
- Без дампа выбор «продолжить» создаёт пустую базу и не вызывает `migrate`.
- Выбор «остановиться» не меняет базу.
- `make db-import` по-прежнему импортирует `cr48940_elitvid_ordered.sql`.
