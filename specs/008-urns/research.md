# Research: Урны

## Хранение урны

- Decision: тип `products.product_type = 'urn'` и своя таблица `urns` (`product_id`, `data` JSON, `material`), как `pots` без `collection`.
- Rationale: у урн нет форм (адрес без коллекции); кашпо и скамейки фильтруются по типу и коллекции, отдельная таблица не задевает их списки, sitemap и счётчики.
- Alternatives: строки урн в `pots` с `collection = 'Urns'` — меньше кода, но урны становятся «кашпо» в данных и в `$product->pot`; отвергнуто.

## Формы админки

- Decision: общие `create_product`/`update_product` + формы кашпо; блок «Форма» только для `pot`; JS кашпо.
- Rationale: поля урны = поля кашпо без коллекции; копия форм дала бы два одинаковых файла по 140 строк.

## Страница списка

- Decision: своя вьюха на `rd-hero` + `rd-grid` + `x-elitvid.works`, без `x-elitvid.collection-page`.
- Rationale: в кадре нет заголовка «Выберите форму» и кнопки каталога, но есть «Примеры работ» — шаблон коллекции этого не умеет.

## Карточка

- Decision: копия `pot_product_page` с `->urn`, крошками «Главная › Наши направления › Урны › {название}» (по образцу кашпо, без уровня формы) и `x-elitvid.cart-buttons`.
- Rationale: кадра карточки нет, пользователь просил копию функционала кашпо.
- Поиск по slug только среди урн: адрес урны с slug кашпо отдаёт 404, а не ошибку.

## Порядок

- Decision: `latest()` как у кашпо; урны заводятся в обратном порядке кадра (MONRO, ORION, VEKTOR, TITAN, SKANDI), чтобы сетка шла SKANDI, TITAN, VEKTOR, ORION, MONRO.
