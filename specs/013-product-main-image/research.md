# Research: Главная картинка товара

## Где хранить признак

- Decision: существующая колонка `images.main_image`.
- Rationale: колонка есть, `ImageService::save` уже пишет её из `image_data[i][main_image]`.
- Alternatives: поле `main_image_id` у товара — лишняя миграция схемы.

## Правило «главная по умолчанию»

- Decision: вычислять при чтении: `images` с `main_image = 1`, иначе картинка с наименьшим `id` (загружена первой). В базу ничего не пишется.
- Rationale: правило само работает после удаления главной и для товаров с одной картинкой.
- Alternatives: проставлять флаг при каждой загрузке и удалении — больше мест для ошибки.

## Одна главная на товар

- Decision: при сохранении картинки товара с `main_image = 1` (загрузка или правка) снимать флаг с остальных картинок того же товара. Только для `imageable_type = Product`.
- Rationale: блог и статические страницы используют тот же флаг по-своему; их не трогаем.
- В формах загрузки JS делает чекбоксы взаимоисключающими.

## Снятие отметки

- Decision: в форме правки картинки скрытое поле `main_image=0` перед чекбоксом; снятие отметки пишет `0`, главной становится загруженная первой (FR-004). Если снята отметка с картинки, которая и так первая, она остаётся главной по правилу.
- Формы картинок блога и статических страниц поле не шлют — `sometimes` в проверке, их поведение не меняется.

## Страница товара

- Decision: `$firstImage = $product->mainImage()`. У `#first_image` атрибуты `data-color`, `data-texture`; `imageUpdater.js` берёт из них начальные значения, при пустых — прежние `marble` / `ivory`.
- Прежний отбор (первая porous/marble с известным цветом) заменяется главной: так требует FR-007.

## Данные

- Decision: миграция данных: у каждого товара, где есть картинка `color = ivory`, `texture = porous`, она (наименьший `id`) получает `main_image = 1`, остальные картинки товара — `0`. Откат — снять флаги у картинок товаров.
- Факт из базы на 2026-11-26: у 27 кашпо по одной пористой ivory; у скамеек и урн цвета нет — работает правило по умолчанию.
