# Feature Specification: Подписи фото при загрузке в галерею «Контента страниц»

**Feature Branch**: `009-page-gallery-captions`

**Created**: 2026-11-25

**Status**: Draft

**Input**: User description: "Баг-фикс: админка «Контент страниц» не сохраняет описание фото, введённое в форме загрузки галереи. Описание, введённое при загрузке, должно сохраняться у соответствующего фото (как в «Статических страницах»). Пустое описание — пусто. Остальное поведение формы не менять. Источник: open-questions.md пункт 19."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Подпись сохраняется вместе с загруженным фото (Priority: P1)

Администратор открывает редактирование контента страницы, выбирает файлы для галереи, под каждым превью вводит описание и сохраняет страницу. Каждое новое фото появляется в галерее со своим описанием — отдельная кнопка «Сохранить» у фото больше не нужна.

**Why this priority**: Это и есть ошибка: сейчас введённое описание молча теряется.

**Independent Test**: Загрузить два фото с разными описаниями через форму контента страницы и проверить, что у каждого сохранилось своё описание.

**Acceptance Scenarios**:

1. **Given** страница без галереи или с галереей, **When** администратор загружает два фото с описаниями «А» и «Б» и сохраняет, **Then** у первого фото описание «А», у второго «Б».
2. **Given** форма загрузки, **When** администратор оставляет описание у фото пустым, **Then** фото сохраняется без описания.
3. **Given** форма контента страницы, **When** администратор сохраняет без новых фото, **Then** поведение как сейчас, ошибок нет.

### Edge Cases

- Описание заполнено только у части фото — у остальных описание пустое, соответствие фото и описаний не сдвигается.
- Запрос пришёл с фото, но без полей описаний — фото сохраняются без описаний, без ошибки.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST сохранять описание, введённое при загрузке, у того фото, под превью которого оно введено.
- **FR-002**: Пустое или отсутствующее описание MUST сохраняться как отсутствие описания, без ошибки.
- **FR-003**: Прочее поведение формы «Контент страниц» (поля страницы, флаг активности галереи, правка и удаление существующих фото) MUST остаться прежним.

### Key Entities

- **Фото галереи**: изображение, привязанное к галерее страницы; имеет текстовое описание.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% описаний, введённых при загрузке, видны у своих фото после сохранения — без второго действия.
- **SC-002**: Загрузка фото без описаний завершается без ошибок.

## Assumptions

- Поведение берётся по образцу формы «Статические страницы», где подписи при загрузке уже сохраняются.
- Ограничения размера файлов сервера (open-questions.md, пункт 20) вне задачи.
